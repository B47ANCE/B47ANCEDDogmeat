# Sandbox settings registry

Project Version: 0.2.0-dev.12

Latest user-directed database/relationship/task proposal: [DATABASE_REDESIGN_SANDBOX.md](DATABASE_REDESIGN_SANDBOX.md). Its logical identity, natural bonding, offline self-care and task/lease semantics supplement/supersede corresponding proposed design details below; no runtime capability or historical evidence is upgraded. The baseline body is preserved.

Runtime diagnostic exception: B47ANCEDDogmeat.PersistenceTestMode is the sole deployed native option, boolean/default false/server authoritative, with existing-save preservation. Exact registry: [runtime-options.json](../src/metadata/runtime-options.json); source and operator behavior: [loadable persistence diagnostic](NATIVE_BOOTSTRAP_TEST.md). The 79 rows below remain future designs under their original proposed identifiers, not deployed options.

M0R design, 2026-10-12. Canonical design rows: [sandbox_settings.json](contracts/sandbox_settings.json). This registry is complete for the approved scope; no settings are shipped or implemented. All defaults/bounds are provisional balancing choices, not native/clinical constants or tested balance. Settings with unproved capability stay unexposed/inactive until their slice passes; requested true never overrides a blocker. The namespace remains provisional with the technical Mod ID.

Server sandbox configuration owns every gameplay setting below. Runtime adapters validate types, finite numbers, bounds, quantization, enums and dependencies on the server; malformed values refuse safely with documented default diagnostics rather than divergent client values. Enum values are stable design tokens; map to supported native option indices only after verifying the installed parser. Double steps are server-normalization contracts, not a claim that the native UI exposes a step field. One normalized reward unit is the future baseline eligible structured completion; its behavior-specific calibration remains a reviewed implementation decision.

Existing-save policies: N=new decisions only/no reroll; P=prospective rates/actions/split time at configuration revision; C=new installations/configuration, preserve existing units; G=safe capability-gated enable/disable, preserve records/objects; L=lower cap blocks additions, never deletes. Full per-row policy, dependency/conflict, parent controls, existing obligations and key data live in JSON. Schema design status is FEASIBLE; each feature capability has a separate EXPERIMENTAL/BLOCKED status and native blockers. No native need rate is modified until its single-writer seam is proved. Disabling Knox prevents new exposures, never cures existing infection: KnoxProgressionRate continues for already infected dogs. Disabling reanimation stops future transitions, not terminal record retention. Parent toggles govern new work; installed electronic door power/lock safety, existing waste cleanup/decay and recovery still operate. Feature disable reconciles irreversible commits before cancellation and never drops existing data.

## Local preferences and internal limits

Bindings/F-keys, hold/toggle radial, controller mappings, UI scale, roster pin/expand and alert/subtitle accessibility are client presentation preferences. They cannot change gameplay time, sound attraction, learning, health, identity, door access or shared difficulty. Do not expose UI coordinates, protocol internals, checksum/schema limits, queue sizes, pathfinding budgets or catch-up segmentation as gameplay micro-settings. Those implementation safety limits require documented rationale and performance tests; population/pack size and decay remain meaningful server choices.

[Localization contract](LOCALIZATION_CONTRACT.md) gives each row Sandbox_<namespace>_<option> and tooltip keys plus enum labels. T-SANDBOX tests each default, boundary, quantization, invalid value, dependency, disabled transition and existing-save rule. Configuration categories do not prove native capability. All options remain NOT IMPLEMENTED and runtime NOT TESTED.


## Implemented presentation option (dev.9)

The 79-setting table above remains future gameplay design. Separately,
`B47ANCEDDogmeat.TailHealthIndicator` is a boolean server sandbox option, default
true, with localized name/tooltip and explicit English fallback. It controls only
Shepherd tail presentation from native replicated health. Disabling restores
neutral; existing saves need no migration or stored flag. Invalid/missing health
uses neutral. Bounds are boolean; radius, cache and per-callback work limits are
internal safety constants. See [motion and tail health](SHEPHERD_MOTION_AND_TAIL_HEALTH.md).
