# Native managed lifecycle proof

Project Version: 0.2.0-dev.9

**D2 BLOCKED; existing Option A NO-GO retained.** A private canonical record can survive loss of a native reference. It cannot prove the old body was withdrawn, that a restored body is authentic, or that no saved duplicate exists. No automatic replacement, marker adoption, positive admission or new guard is introduced.

The current [ledger](database-authority-proof-evidence.json) rehashes selected animal/worker/object inputs. The detailed [ten-step source trace](NATIVE_SAVE_LOAD_AUTHORITY_TRACE.md), [exclusive-seam assessment](EXCLUSIVE_ADMISSION_SEAM_ASSESSMENT.md) and [reconstruction provenance](NATIVE_RECONSTRUCTION_PROVENANCE.md) remain applicable to their exact packaged hashes. Their earlier observed HEAD/version/runtime labels are not rewritten. The 59-site construction inventory is bounded evidence, not complete graph proof.

P05 confirms inherited IsoObject.Serialize returns true. No verified managed-only exclusion policy was found in the bounded inspected source. Replacing a Lua table field does not override native Java virtual dispatch. P06 confirms removal is a mutation, not proof that every native saved copy is absent. Loose IsoAnimal/IsoObject differ from package; no runtime compatibility inference is made from these packaged methods.

The required alternatives remain (a) verified exclusion from every ordinary restoration path plus recoverable creation/withdrawal, or (b) authentic reconciliation of every supported representation before any replacement. Neither is demonstrated. A current-process map, UUID, marker checksum, first match, saved location or online ID cannot supply the missing origin/absence evidence.

Required negative outcomes remain: one logical dog never receives two authorized bodies; copies never gain ownership; stale bodies are not adopted; restore never overlaps a replacement; uncertainty preserves private records and quarantines authority. Existing offline equality/refusal tests support current refusal behavior only. Physical duplicate prevention, restart/streaming/transport/death behavior and ordinary-client exploit closure are **NOT TESTED in PZ**.
